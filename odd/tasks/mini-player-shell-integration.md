## Objective

Wire `mini-player.svelte` to the native window: make the compact mode frameless, non-resizable and restorable, and give the user a way in and out of it.

## Problem & Motivation

`mini-player.svelte` shipped in #102 but is imported by nothing — `windowState` still has zero UI consumers. Until this slice the compact mode cannot be entered, so none of #102 is observable in the app.

## Scope Boundaries

**In scope**

- `setDecorations` / `setResizable` on the native client seam, applied inside the existing port methods
- The two missing Tauri v2 capability permissions
- Compact-mode branch in `+layout.svelte`, including the global `Escape` handler
- The `Header` trigger, gated on `windowState.isSupported`

**Out of scope**

- Any change to `IWindowShell` — see Deviation 1
- Rounded corners or a drop shadow on Windows 11 (needs the `window-shadows` crate; touches `Cargo.lock`)
- Anything in `src-tauri/src/` or `Cargo.toml`

## Key Invariant — chrome before size

The single riskiest part of this slice cannot be caught by a Vitest run, because it needs a real native window: **the order of native calls**.

Tauri's `setSize` sets the **outer** size. While `decorations` is `false`, outer equals inner. So:

- Entering: if we resized to 280x64 with decorations still on, then removed decorations, the window would end up 280x64 _including_ a title bar it no longer has. Wrong.
- Restoring: if we resize to 800x650 while frameless and only then re-enable decorations, Windows adds ~30px of title bar back and the client area ends up ~620x620. Wrong.

Therefore, in **both** directions: **configure the chrome first, then set the size.** This is encoded as a JSDoc invariant on `IWindowShell` and asserted by call-order tests in the adapter suite.

```
enterMiniPlayer   setDecorations(false) → setMinSize(MINI_MIN) → setSize(dimensions)
                  → setResizable(false) → setAlwaysOnTop(true)

restoreMainWindow setAlwaysOnTop(false) → setResizable(true) → setMinSize(MAIN_MIN)
                  → setDecorations(true) → setSize(MAIN)
```

### [x] TASK-3: Compact-mode branch in `+layout.svelte`

- **Route**: Direct inline
- **Files**: `src/routes/+layout.svelte`
- **Acceptance**: when `windowState.isMiniPlayer`, the layout renders only `<MiniPlayer />` — no `Header`, no `SettingsDrawer`, no `DailyCounter`, no `{@render children()}`. Otherwise byte-identical to today.
- **Why the layout and not the page**: `+layout.svelte` owns `Header`, `SettingsDrawer`, `DailyCounter` and the children slot. Branching only in `+page.svelte` would swap the tab content but leave a header inside a 280x64 window. One conditional in one place.
- **Decision**: the global `Escape` listener lives here, not in `mini-player.svelte`. Escape is a window-level concern, and `mini-player.svelte` was built as a presentational component with an injected `windowState`; a global key listener would change its character.

### [x] TASK-4: `Header` trigger

- **Route**: Direct inline
- **Files**: `src/lib/components/layout/header.svelte`, `src/lib/components/layout/header.svelte.test.ts`, `src/lib/state/windowState.svelte`, `src/lib/state/windowState.test.ts`, `messages/en.json`, `messages/es.json`
- **Acceptance**: a control that calls `windowState.toggleMiniPlayer()`, rendered **only when `windowState.isSupported`**
- **Added**: `WindowState.isSupported` getter delegating to the shell. The port capability existed but was not reachable from the UI; without it the trigger cannot be gated.

**Two problems found while implementing this, both resolved here.**

1. **Zen Mode made the trigger unusable.** `header.svelte` applied `opacity-0 pointer-events-none` to the `<header>` root while the timer ran, so the trigger would have been invisible during a focus block — the only time compact mode is worth entering. The compact mode has to be entered _before_ switching to the editor; otherwise the user is Alt+Tab-ing to Pomody anyway, which is exactly what the feature removes.
   Fix: the Zen rule moved from the `<header>` root onto each slot, because **a CSS `opacity-0` on an ancestor cannot be undone by a descendant**. The brand, the nav and the settings trigger keep receding exactly as before; only the compact trigger stays reachable. The two existing tests asserting Zen classes on `<header>` were updated to assert them on the nav and the settings button — the intent is unchanged, only the scope.
2. **`<svelte:window>` cannot live inside a block.** Svelte rejects it inside `{#if}` (`svelte_meta_invalid_placement`). It now sits at the component top level with the guard in the handler, which `WindowState.restore()` already provides.

**Decision**: gated on `isSupported`. On the web build `enterMiniPlayer` is a safe no-op, so an ungated trigger would be a control that visibly does nothing.

## Deviations

1. **`IWindowShell` is NOT extended.** `decisions.md` §4 item 1 said to add `setDecorations` and `setResizable` to the port. That was wrong: the port describes capabilities, and "enter compact mode" already _is_ the capability. Exposing them would teach Tauri to the domain and force `FakeWindowShell` and every consumer to change for something the method name already implies. The seam (`TauriWindowClientLike`) grows instead, and the port methods absorb the calls. `decisions.md` will be corrected.
2. **Compact-mode branch in `+layout.svelte`, not `+page.svelte`.** Recorded in TASK-3.
3. **The compact trigger is exempt from Zen Mode.** Recorded in TASK-4. This is a deliberate change to a previously shipped behaviour, so it needs the Tech Lead's explicit sign-off — which it has.
